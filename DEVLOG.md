- **Design decisions / tradeoffs:**
  - **Collapse:** an exact projection (e.g. 0.333) would be rounded to 0.1 by the number spinner, which writes the rounded value back to the store (checked in the `svelte-number-spinner` source: its reactive `updateValues` calls `roundToPrecision`), leaving det slightly off 0. So the second column is snapped to the closest multiple of the smallest 0.1-grid step along the first column's line (direction (p, q)/gcd(p, q) for first column (p/10, q/10)), clamped to ±3. Tradeoff: the result is the closest *grid* point, not the exact closest point.
  - If the first column is zero, the determinant is already 0 and the matrix is left unchanged.
  - Shortcut buttons in V3 are disabled when the result would leave the ±3 range or the 0.1 grid.
  - `AreaDetChart.svelte` is kept because V2 still uses it.
- **Issues Encountered:**
  - Found while designing the V3 collapse: V2's "Shrink first column ×½" can produce values off the 0.1 grid (e.g. 0.3 → 0.15), which the spinner then rounds, so the determinant is not exactly halved. This bug is **left in V2** (V2 is frozen for comparison) and fixed in V3 by the grid check.
