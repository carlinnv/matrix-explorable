# Development Logging Instructions

This project is part of an academic assignment requiring documentation of the iterative development process.

Maintain a file named `DEVLOG.md` in the project root.

After completing each meaningful implementation step, debugging session, or revision, append a new entry to the development log.

Each entry should contain:

- **Task:** My prompt (what I asked you to do)
- **Changes:** What was implemented or modified
- **Files Modified:** Relevant source files
- **Issues Encountered:** Bugs, unexpected behavior, or limitations
- **Resolution:** How the issues were addressed
- **Testing:** Tests performed and their results
- **Next Steps:** What remains to be done

Additional requirements:

1. Keep entries concise, factual, and chronological.
2. Never overwrite or delete previous entries.
3. Distinguish between planned changes and completed changes.
4. Do not invent tests, observations, problems, or user feedback.
5. Record significant design decisions and tradeoffs.
6. Note when an implementation was suggested or generated by Claude Code.
7. Do not claim that I personally tested or approved a feature unless I explicitly confirm it.
8. After each major milestone, ask me for a short reflection on what worked, what was confusing, and what I would change.

The purpose of this log is to help me reconstruct the development process and write my own final reflection report.
